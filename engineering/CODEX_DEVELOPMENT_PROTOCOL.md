# Codex development protocol

1. Read AGENTS.md and applicable sprint charter. Fetch canonical rally-one/develop, verify actual SHA, PR merge ancestry and clean workspace. Preserve main and all recovery refs. Never infer current state from conversation hashes.
2. Inventory changed owners and consumers before coding: shared tokens, shell/navigation, identity, storage, permissions, fixtures and accessibility fan out beyond filename scope. Define acceptance criteria and exact commands first.
3. Record classification and reason in PR. Tier1: genuinely isolated presentation; relevant units, build, scoped rendering, accessibility and approved visual comparisons. Tier2: bounded component behavior with demonstrated ownership; relevant units/integration, journeys, cross-browser, accessibility, visuals, build and provenance. Tier3: security, privacy, storage, shared infrastructure, validator/workflow changes, canonical integration or release preparation; comprehensive applicable suite including protected historical/security/integration checks. Unknown or mixed dependencies escalate to Tier3. Approximate targets 5–15 / 15–30 minutes for tiers1/2 are goals, not permission to omit tests.
4. `node scripts/validation-plan.cjs <verified-base> HEAD` produces advisory exact-SHA/file inventory. Only known isolated Connect CSS receives Tier1 local advice; all other inputs default Tier3. Tier2 needs documented human dependency review; it is not an automatic filename shortcut. Both embedded and standalone Connect consumers remain required. Current remote CI always runs Tier3, even for Tier1 local advice. Do not add classifier-based workflow conditions without separate validated impact analysis.
5. Implement smallest coherent change on isolated branch. Focused local tests first; investigate failures before broad validation. A narrow diagnostic pass never clears a failed full gate. Record logs/artifacts, exact selector/comparison, raw pixel bounds and evidence-supported cause; label hypotheses.
6. Run required tier locally before consolidated push. Avoid rerunning identical work only when source tree, lockfile, validator configuration, fixture/clock/browser/OS/context identities and successful evidence are all established. Different build contexts are different inputs. No reuse of failed, missing, canceled, stale or unverified results. Current CI has no cross-run acceptance cache.
7. Push draft PR targeting canonical develop. Full CI remains mandatory: functional and visual jobs run independently, and always-running preview-qa requires both success. Failure/cancellation/skip cannot become aggregate success. VersePlay foundation remains separate. CI/workflow edits are validated by full CI, not by their own risk classifier: no circular selection loophole.
8. Inspect every failed step and named job artifact. Download GitHub artifacts through connector if redirect download fails. Inspect actual pixels before assuming anti-alias or portrait drift. Full historical sources and zero raw tolerances are immutable; explicit owner approval required for new visual source reference.
9. Verify Netlify immutable deployment metadata (exact SHA, PR, branch, preview context), clean-archive build output and deployed file bytes. Never deploy production or use credentials/live member records. Report exact head, CI URLs/counts, comparisons, risks and manual gates.
10. Stop at reference approval, physical Safari/VoiceOver/final visual acceptance or leadership/security decisions as applicable. Record owner-reported acceptance honestly; missing device details remain missing. Separate explicit merge authorization is mandatory. Never modify canonical or recovery refs directly during feature work.

## Diagnostics and acceptance
Keep aggregate check names stable for branch protection. Functional artifact: rally-point-preview-qa-functional; visual artifact: rally-point-preview-qa-visual; VersePlay artifact unchanged. Failure blocks merge. Inspect failed script/stack and results.json, then before/after images; report probable cause only with evidence and next focused diagnostic. Preserve original failed artifacts. Manual admin verification of required contexts is needed where API permissions are denied.
