## Design intention

Move from a navigable category directory to the beginning of a real conversational experience, without pretending the deterministic local prototype is a generative model. Preserve the selected F-09 cream / bright Citizen-red / pastel board and keep a **single Ask Rally entry**. When opened, the sheet now visibly retains up to three previous question/answer summaries, displays one current answer with expandable source rationales, suggests up to three **contextual** next questions, and collapses unrelated starter topics under “Explore other topics.”

### Sample flow

1. Member asks “What’s happening this week?” → answers from next fictional Wednesday and Sunday dates, membership-scoped.
2. “What time?” is ambiguous when both commitments are relevant → **“Which one do you mean?”** with Wednesday/Sunday follow-up chips, not a guessed commitment.
3. “What time is Wednesday Group?” → actual sample date, time and group location; conversational context now points at **group**.
4. “And Sunday?” → actual sample Welcome Team schedule; context switches to **serving**.
5. “Can I confirm that?” → context-specific serving response with a separate **Confirm serving** button; the text input does **not** commit.
6. “Yes” → still cannot commit; only the explicit button invokes the existing guarded local response handler.
7. After actual button confirmation, the current answer re-derives from the source and shows “already confirmed.” The team response and Today board sync immediately.
8. Closing the sheet clears the entire conversational history, last referent, typed question and feedback. Reopening begins anew.

## Behavior contract

- `RallyPersonalCompanion.respond(query,sources,prior)` is pure. It never mutates fixtures, writes transcripts or accesses a network.
- The recognized explicit subjects are **Wednesday Group, Sunday Welcome Team and Scripture**. A short pronoun can inherit a subject **only inside the open sheet**.
- Clarification is preferred whenever a subject is ambiguous. Suggestions come from a fixed allowlist of recognized follow-up IDs and are limited by membership.
- All schedule and status fields derive from the current guarded `RallySmartDashboard.model` and F-09 `RallyPriorityBoard.derive`, **not** from text previously generated by Rally. Prior text is not authoritative and never grants permission.
- If membership is revoked (or the demo is a guest), any follow-up must pass the **current** membership check. Team and group private details never cross scopes. Leader-specific data is only surfaced through the existing authorized source.
- "Can I confirm that?", "yes", and "sure" are conversational requests, never silent side effects. `f10-confirm` only supports existing deliberate local RSVP/serve actions with current membership and pending-state guards. No auto-RSVP, auto-prayer, auto-read or auto-message.
- Conversation history is a bounded in-memory array of at most 3 previous visible turns, HTML escaped. It does not enter localStorage or the legacy/modern message archives. On modal close or navigation, it is discarded.
- Unknown/open-ended requests still disclose the supported prototype topics. There is **no live LLM, background agent, real account connection or church data**.
